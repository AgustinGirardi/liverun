# Plan: migrar la app móvil de Expo SDK 54 a 58

**Estado: sin ejecutar.** Sale de la auditoría del 21/10 (`docs/audits/2026-10-21.md`, mejora 5). No toca código: es el plan para hacerlo en su propia tarea, con prueba en dispositivo.

## Contexto

`npm audit` en `mobile/` da 71 vulnerabilidades (1 crítica en `shell-quote`, 54 altas y 16 moderadas). Son todas transitivas y vienen casi todas del tooling de Expo y Metro, no del código que corre en el teléfono. `npm audit fix` solo no alcanza y `npm audit fix --force` propone saltos con cambios que rompen. Como las vulnerabilidades están en el tooling que trae cada SDK, la salida es subir de SDK (a confirmar contra las notas de versión al empezar).

Hecho en el mismo trabajo de la auditoría: `@types/jest` salió de `dependencies` (quedó en `devDependencies`).

## Decisión previa (bloquea todo lo demás)

`mobile/AGENTS.md` dice que el proyecto se bajó de SDK 56 a 54 el 11/06/2026 porque **Expo Go del App Store de iOS solo soportaba SDK 54** y Agustín prueba en iPhone. Antes de empezar hay que resolver una de dos:

1. **Confirmar que Expo Go en iOS ya soporta el SDK destino.** Si sí, se puede seguir probando como hoy.
2. **Pasar a development builds** (`eas build --profile development`). Es lo que hace falta de todos modos para probar lo nativo (GPS en segundo plano, mapas, `expo-updates`). Cuesta un build por cada cambio nativo.

Sin esta decisión no tiene sentido tocar versiones.

## Enfoque: un SDK por vez

Saltar de 54 a 58 de una sola vez mezcla los cambios de cuatro versiones y deja un diff imposible de depurar. Se sube 55 → 56 → 57 → 58, cada uno en su commit y con la suite verde.

Para cada salto `N`:

1. Leer las notas de versión del SDK `N` (Expo changelog y la guía de upgrade de React Native de esa versión) y anotar los cambios que rompen.
2. `npx expo install expo@^N` y después `npx expo install --fix` para alinear todos los paquetes `expo-*` y las librerías nativas.
3. `npx expo-doctor` y resolver lo que marque.
4. Verificar: `npx tsc --noEmit`, `npm run lint`, `npm test` y `npx expo export --platform web`.
5. Commit con el SDK en el mensaje.

## Puntos de riesgo conocidos en este repo

| Zona | Por qué preocupa |
|---|---|
| `expo-router` y `NativeTabs` | `AGENTS.md` ya avisa que la API de NativeTabs cambió entre versiones. La tab bar propia está en `mobile/src/components/app-tabs.tsx`. |
| `react-native-reanimated` y `react-native-worklets` | Están atados a la versión de RN. `animated-icon.tsx` usa `scheduleOnRN` de worklets. |
| `react-native-maps` | Pinneado exacto (1.20.1). Revisar la matriz de compatibilidad de cada SDK. |
| `expo-location` y `expo-task-manager` | El registro de salidas con GPS en segundo plano (`src/lib/location-task.ts`) es lo más delicado de la app. |
| `expo-updates` y `runtimeVersion` | La política es `fingerprint`: cada salto cambia la huella y **ningún build instalado va a tomar la OTA**. Hace falta un build nuevo (ver `PENDIENTES.md` §2 y `mobile/README.md`). |
| Jest | `jest-expo` está atado al SDK (`~54.0.18`); sube junto con él. Revisar que los 9 suites de `src/lib/__tests__` sigan en verde. |
| Lint | `eslint-config-expo` también sube. Hoy el lint corre con cero avisos permitidos: si el config nuevo agrega reglas, hay que cerrarlas antes de mergear. |

## Prueba en dispositivo (checklist al final de cada salto grande y obligatorio al final)

Android (build real, no solo Expo Go):

- [ ] Arranque en frío, splash y login (email y Google).
- [ ] Registrar una salida corta con GPS **con la pantalla apagada** y ver que el recorrido queda completo.
- [ ] Tab bar: FAB de correr (toda la superficie responde), Predictive Back (Android 13+).
- [ ] Ranking: cambiar alcance y período, scroll con el podio colapsable.
- [ ] Tema claro y oscuro, texto al 200 %.
- [ ] Compartir la tarjeta de una salida.
- [ ] La OTA: publicar un update trivial y comprobar que el build lo toma.

iOS (si se prueba ahí): lo mismo, más permisos de ubicación "siempre".

## Cierre

- Bajar `npm audit` y anotar cuántas vulnerabilidades quedan (la meta es cero críticas y cero altas; las moderadas de tooling se evalúan una por una).
- Actualizar `mobile/AGENTS.md` (versión de SDK y nota de Expo Go), el README (SDK y RN) y `PENDIENTES.md`.

Migrar a la nueva arquitectura de RN si no viene forzada por el SDK, y rediseñar pantallas.
